# GALS — Паспорт проекта

## Что это

Персональная система управления жизнью **GALS** (ранее P&R). Desktop-приложение под
Windows: учёт активностей, регулярных обязанностей, измерений, субъективных оценок и
метрик по двум осям (attention / satisfaction). Девиз: «Меньше учёта — больше
результата».

Философия и семантика — `architecture.md`. Бэклог — `roadmap.md`. Карта файлов —
`project_structure.md`.

## Стек

- **ОС:** только Windows (desktop-часть).
- **Язык:** Python 3.10.9 (пины — в `requirements.txt`).
- **GUI:** Tkinter + `tksheet` (таблицы), `tkcalendar` (календарь), `tkTimePicker` (стоит в окружении, в `src/` не импортируется).
- **БД:** SQLite (`data/gals.db`).
- **Файлы:** `openpyxl` (Excel), `json` (std), `python-dateutil` (время), `requests` (REST-синхронизация).
- **Инструменты:** pip, pytest, setuptools, wheel (все с пинами в `requirements.txt`).
- **Веб-часть:** PHP + MySQL, деплоится на `slqa.ru/z/` (см. «Внешние сервисы»).

## Запуск

Только через **PyCharm**: открыть `gals.pyw`, выбрать конфигурацию «Current file»,
нажать Run. Точка входа — `gals.pyw` → `src/app_ui.py`.

**Prod-версии нет.** Build-скриптов и пакетов нет.

## Тесты

**Автотестов нет.** `pytest` лежит в `requirements.txt` как подготовка.

- Проверка сейчас — только ручная: запуск приложения и сценарии из TD-17
  (`roadmap.md`).
- Планируется на релиз 2 (TD-17); каталог (`tests/` в корне или `src/tests/`) и
  команда — тогда же.

## Миграции

- **Каталог:** `migrations/`, файлы `NNN_краткое_описание.sql`, нумерация сквозная.
- **Применение:** `src/database.py` (`Database._apply_pending`) по
  `PRAGMA user_version`.
- Полные правила (атомарность, FK, бэкап вручную) — `architecture.md`, §3.

## Структура

**Слоистая архитектура** (Layered Architecture). Зависимости идут только вниз:

1. **БД + триггеры** — `data/gals.db` (SQLite). Схема — `migrations/*.sql`;
   инварианты (timestamp-триггеры, защита «Ночного сна», уникальный индекс сна,
   `ON DELETE RESTRICT`) держатся на уровне БД.
2. **Класс доступа к БД** — `src/database.py`. Соединение, транзакции, применение
   миграций.
3. **Репозитории** — `src/*_repo.py`. Единственное место в коде, где пишется SQL.
   Верхние слои не знают, какая под ними СУБД; правило действует и для desktop, и для
   веб-части.
4. **UI** — `src/app_ui.py`, `src/*_tab.py`. Вкладка сейчас совмещает интерфейс и
   бизнес-логику сценария (**Smart UI**). Часть логики вынесена в сервисы:
   `src/*_service.py`, `src/indicator_calculator.py`, `src/score_calculator.py`.

**Моделей в смысле ORM нет.** ORM (Object-Relational Mapping) — библиотека, которая
превращает таблицы в Python-классы, а SQL — в вызовы методов (SQLAlchemy, Django ORM).
У нас вместо этого прямой SQL в репозиториях.

**Smart UI — технический долг.** Бизнес-логику из `*_tab.py` планируется вынести в
сервисный слой (см. `roadmap.md`), чтобы её можно было тестировать отдельно от UI.

Ядро и утилиты: `app_config.py`, `constants.py`, `database.py`, `datetime_utils.py`,
`defaults.py`, `score_calculator.py`, `ui_utils.py`.

Полное дерево файлов — `project_structure.md`.

## Внешние сервисы

Веб-часть — **часть системы**, но с desktop-приложением общается **только через REST
API**. Сейчас **законсервирована** (пользуемся, но не развиваем; технические долги —
TD-16 в `roadmap.md`).

- **Хостинг:** `https://slqa.ru/z/`.
- **Бэкенд:** PHP + MySQL. СУБД и схема скрыты за REST API; desktop о них ничего не
  знает.
- **API:** `POST /install`, `POST/GET /events/`, `DELETE /events/{id}`; авторизация по
  API-ключу.
- **Назначение:** приём событий «Подъём»/«Отбой» с телефона, когда компьютер выключен.
  Локально складываются в `web_time_events`, из них по команде создаётся активность
  «Ночной сон».
- **Секреты:** `z/config/.env` (`DB_*`, `API_KEY`), защищён `.htaccess`, в git не
  коммитится.
- **Деплой:** локальные `z/index.html`, `z/api/*`, `z/config/*` копируются в
  `public_html/z/…` на сервере. Инструкция — `z/config/README.md`.

## Стиль

- **Formatter / linter:** **не настроены** (в `requirements.txt` нет). Инструменты
  были неизвестны автору на момент создания проекта; настройка — в техдолге
  (`roadmap.md`). Кандидат — `ruff` (format + lint).
- **Язык:**
  - идентификаторы, имена таблиц/колонок, ключи `preferences` — **английский**;
  - документация и UI — **русский**;
  - термины без устоявшегося перевода или часто используемые в английском (`SQL`,
    `git commit`, `smoke-test`, `layout`) — **как есть**.
- **Комментарии в коде** — русский. Объясняют **почему** сделано именно так
  (неочевидное решение, обход бага, требование внешней системы), а не **что** делает
  код. Код сам показывает «что»; комментарий-пересказ кода — шум.

## Ограничения

- **ОС:** только Windows (запуск через `gals.pyw`, `iconbitmap`, поведение Tkinter).
  Все пути в коде — относительны корня проекта.
- **Часовой пояс:** жёстко UTC+3. `+03:00` в ISO-строках — часть контракта БД (TD-18).
- **Секреты в репозиторий не коммитим:** `z/config/.env`, `data/gals.db`,
  `data/*.db-journal`. `data/gals.db` создаётся при первом запуске.
- **Бэкап БД** — вручную, перед миграциями.
